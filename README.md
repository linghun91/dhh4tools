# dhh4tools

《大航海时代4 HD》存档修改器源码。窗口程序，读写 `Documents\KoeiTecmo\DK4HD\Savedata` 里的 `savedat00.dk4` 到 `savedat10.dk4`，也可改四个语言版主程序里的等级、属性、技能和港口商业/军事上限。

## 仓库里有什么

| 文件 | 作用 |
| --- | --- |
| `src/` | 全部源码（C11，Win32 API），按功能分目录，见下节 |
| `build.bat` | 构建脚本，优先 MinGW gcc，其次 MSVC |
| `dk4save.rc` | 资源脚本，把清单嵌进 exe |
| `dk4save.manifest` | Common Controls 6、DPI、长路径 |
| `mingw-endfile.specs` | gcc 链接时用的 specs，避免 WinLibs 默认 endfile 冲突 |
| `README.md` | 本说明 |

没有第三方库。链接的是系统自带的 `comctl32`、`comdlg32`、`gdi32`、`user32`。

不进仓库的：`dk4save.exe`（构建产物）、`dk4save.ini`（运行时记下的游戏目录）、`.o` / `.obj` / `.res`、`obj/`（中间文件）。

## 源码结构

```
src/
  main.c                程序入口 WinMain
  common/               与业务无关的基础设施
    platform.h          Win32 编译设置与系统头文件（所有文件最先包含）
    bytes.[ch]          小端读写
    backup.[ch]         写入前备份（name.bak 与带时间戳的备份）
  save/                 存档
    save.h              存档格式（偏移、记录结构）与本目录全部接口
    save_file.c         读取、校验和增量、写入、旧版损坏检查
    person.c            人物记录：六维、等级、势力、名字
    sailor_names.c      人物 0..86 的显示名
    save_dir.c          存档目录与存档栏文件名
  exe/                  主程序文件层（不含具体补丁）
    game_exe.[ch]       四个语言版主程序：定位游戏目录、读写（带备份）、还原原版
    pe.[ch]             PE 解析：.text 范围、RVA 换算、导入表
    x64asm.[ch]         x64 机器码拼装（asm_*）与字节模式查找（pat_*）
  patch/                主程序补丁
    caps.[ch]           等级/属性/技能/港口上限；读写全部补丁的总入口
                        read_exe_image() / patch_exe_image()
    cave.[ch]           补丁共用的代码洞格式（魔数、头、原字节表、还原）
    stack/              商品堆叠（DK4STK5）
      stack.h
      stack_slot.c      买卖与货物代码里的补丁点，移除旧版布局
      stack_cave.c      识别各版本堆叠代码洞，读回堆叠数
      stack_apply.c     生成并安装堆叠补丁代码
    fashion.[ch]        卖流行品参数（DK4FSH1）
    proxy_buy.[ch]      地方舰队买货亏损修正
    game_patch.[ch]     对游戏目录下所有语言版主程序批量读取 / 写入
  ui/                   界面
    app.[ch]            主窗口全局状态 g、控件 id、DPI 缩放 S() 等
    widgets.[ch]        控件小工具（列表视图、数字输入框）
    main_window.[ch]    主窗口：创建控件、布局、窗口过程
    person_editor.[ch]  人物列表与编辑表单
    save_slots.[ch]     存档栏，打开 / 刷新 / 保存
    cap_window.[ch]     "游戏上限"窗口
```

依赖只能向下：`ui` → `patch` → `exe` / `save` → `common`。`save` 与 `exe`/`patch` 互不引用。

约定：

- 一个模块一对 `.c` / `.h`；一个功能拆成多个 `.c` 时共用一个头文件（`save/save.h`、`patch/stack/stack.h`）。
- 只在本文件用的函数、常量一律 `static`；别的文件要用的才写进头文件。
- 头文件都有 include guard，并先包含 `common/platform.h`；`.c` 先包含自己的头文件。
- include 路径从 `src/` 算起，如 `#include "patch/stack/stack.h"`。
- 整个 `src/` 里 `.c` 文件名不能重名（MSVC 把 `.obj` 放进同一目录）。
- 注释用简短中文。

新增功能放哪里：

- **新的主程序补丁**：在 `patch/` 下新建 `xxx.c` / `xxx.h`，复杂的建子目录（参照 `stack/`）。需要能还原原版时用 `cave.h` 的代码洞格式，另起一个魔数。要在界面上调的数值加进 `caps.h` 的 `CapValues`，在 `caps.c` 的 `read_exe_image()` / `patch_exe_image()` 里调用，输入框加在 `ui/cap_window.c`。
- **新的存档字段**：偏移写进 `save/save.h`，读写放 `save/` 下对应文件。写入的字段要在 `save_file.c` 的 `field_at()` 里登记宽度，否则保存时算不出校验和、会拒绝写入。
- **新的窗口**：`ui/` 下新建 `xxx_window.[ch]`。
- `build.bat` 自动编译 `src/` 下全部 `.c`，加文件不用改它。

## 构建

Windows。任选一套编译器：

1. [WinLibs MinGW-w64](https://winlibs.com/)（UCRT），或
   `winget install -e --id BrechtSanders.WinLibs.POSIX.UCRT`
2. Visual Studio，带 MSVC 和 Windows SDK

在本目录运行：

```bat
build.bat
```

成功后会在本目录生成 `dk4save.exe`。改主程序前请完全退出游戏。

## 备份与还原

- 第一次保存存档、第一次写入主程序时，原文件存为 `文件名.bak`，以后不再覆盖。
- 之后每次写入前的文件另存为 `文件名.日期-时间-毫秒.bak`（例如 `DK4HD_sc.exe.20261030-153012-123.bak`），每个文件只留最近 10 份。
- 备份失败时不写入。
- “游戏上限”窗口的“还原原版主程序”用 `DK4HD_*.exe.bak` 把四个主程序还原成第一次写入前的样子；还原前的主程序同样另存一份。存档不受影响。

## 存档人物段与校验和

游戏从存档 `0x2C03` 起按人物 id 存 235 条记录：id 0–86 每条 25 字节（势力、六维、两段经验、HP、身心、装备），id 87–234 每条只有 2 字节（势力和一个只增不减的字节），他们的六维和经验不进存档。`0x35AA` 起是主角记录。

- 修改器只列出、只改 id 0–86 和主角。
- 存档头 `+0x18` 是正文各字段数值之和。保存时，修改器把改动字段的差值加到 `+0x18` 上，所以游戏存过的档改完后读档不再弹“所储存的进度有可能损坏了”。改动落在修改器不认识的字段上时拒绝写入。
- 2026-11-06 之前的版本按 `0x2C00` 起 98 行、每行 `0x19` 读写。第 0–86 行字段正好对上；第 87–97 行在存档里并不存在，改它们（尤其主角是拉斐尔时的批量修改）会把 id 88–219 的配角势力写成 255、196 或 0。那些版本也不重算 `+0x18`。
- 打开存档时如果发现配角势力越界，状态栏会提示。用同目录 `.bak` 里的原值恢复这些字节，再按差值修正 `+0x18`。

## 商品堆叠

“游戏上限”窗口的“同商品堆叠”可填 1 到 255（件数存在货物记录的一个字节里，所以最多 255）。填 1 还原原版。

- 交易所里这次买的同一商品先堆在同一格，满 N 件才再占一格。卖出、退货、全部卖出、撤回卖出和交易统计都按件数算。
- 左键是 1 件，按住 Shift 左键是整格：
  - 市场商品：左键买 1 件；Shift 把下一件落进的那一格买满（那格已有 3/10 就再买 7 件，没有未满的格就新开一格买 10 件），钱、货或舱位不够时买到为止。
  - 船舱里原有的货：左键卖 1 件；Shift 整格卖。
  - 船舱里这次买的货：左键退 1 件；Shift 整格退。
  - 卖出列表：左键撤回 1 件；Shift 整条撤回。
  - 单件优先并进同货的未满格：卖出时并进卖出列表里记录相同（货物、等级、买入价等，除件数外每个字节都一样）且未满 N 件的那条；撤回时并进船舱里同样的、不是这次买的未满格。没有可并的就占一个空位。最后 1 件并过去后原来那格清空。卖出列表满了、没空舱时什么都不变，和原版一样。
- 价格栏放得下（不超过 6 个字符，如 `9x9999`、`99x999`）就显示一行“件数x单价”；放不下就分两行，上行“件数x”，下行单价。
- 存档里没有件数这个字节。写入后件数放在存档里买入价的最高字节里一起存、读，读档后还原。原版存档读进来每格都是 1 件。
- 玩家势力的舰队（地方舰队、下属 NPC 舰队）自动买货时，每格装到 N 件，载货量按“舱位 × N”算；自动卖货按件数结算。其他势力（别的商会、海盗等）的货物存法不同，保持原版。
- 委托、剧情、事件检查和扣除货物都按件数算。例如委托要 5 个红酒：一格堆了 30 个就算够，交付时这一格扣 5 个、剩 25 个；不够时从下一格接着扣，扣空的格子清掉。剧情送货仍是一格一件。王宫“送礼”和广场“寻求支持”原版就只扣 1 件，现在也是从一格里扣 1 件。
- 整理货物界面：整理货物、卖船或入坞时把货挪走、海战后装战利品、广场传教士“发放交易品”都用这个界面。每格多于 1 件时右下角显示“x件数”。左键点船舱格挪 1 件到待处理区、点待处理区的格挪 1 件回当前船舱；按住 Shift 点是整格挪（原版做法）。单件同样先并进记录相同的未满格，没有就占空位；待处理区满了或当前船没有空舱时什么都不变。从待处理区放回船舱时件数不变（旧版会变成 1 件）。
- 广场“发放交易品”（捐赠）按件数结算：
  - 疫病、饥荒、缺货的城市，需要的那类货发够 `5 + 商业发展度 ÷ 500` 件就解除（旧版一格只算 1 件，一整格药品也救不了）。
  - 可能在别的城市带出这种货的流行：判定加成和新流行的等级用件数，最多按 25 件算（原版整支舰队 25 格，流行等级存在一个字节里）。
  - 文化圈卖价回升和该类货需求下降用件数。需求公式里有个“单价之和 ÷ 件数”的除数，件数多了会变成 0 让游戏崩溃，补丁在这里按封顶值 25 处理，并用 64 位算乘积。原版数量范围内结果和原版一样。
- 存过堆叠货物的存档不要再用原版主程序读：原版会把件数当成买入价的一部分。

补丁代码放在 `.text` 开头增量链接跳板表后面的 int3 空位里，开头写着 `DK4STK5`，末尾存着每个改动点的原版字节，填 1 或“还原原版主程序”时原样放回。旧版（`DK4STK4`、`DK4STK3`，以及上限 9 的 `DK4STK2`）写入的主程序会先被还原再写新版；读取时如果发现是旧版，状态栏会提示再点一次“写入主程序”。

没改的：接舷战打输时被抢走的货仍按格数计（原版规则，按被俘船的货舱数整格拿走），对方因此得到的金币按每格 1 件的目录价算，只影响 NPC 的钱。选船、船只信息里的货物小图标不显示件数。

## 卖流行品

玩家在交易所确认交易时，这个城市的两种流行品按卖出件数影响占有率和介绍信/推荐信（堆叠补丁装上后就是件数，不是格数）。原版规则里的常数是按一格一件定的，“游戏上限”窗口里可以改：

| 输入框 | 原版 | 作用 |
| --- | --- | --- |
| 流行品门槛(每格) | 1 | 占有率不到 80 时，每种流行品要卖到 `舰队货舱格数 × 门槛 ÷ 2` 件（向上取整）才加占有率。填 0 表示卖一件就算 |
| 占有率涨幅除数 | 6 | 达到门槛后占有率加 `两种流行品件数 ÷ 除数 + 1`，游戏本身封顶 100 |
| 介绍信件数 | 10 | 占有率 80 以上，卖到这个数（到推荐信件数之前）给介绍信 |
| 推荐信件数 | 16 | 卖到这个数给推荐信；已有介绍信时升级成推荐信。必须大于介绍信件数 |

“按堆叠等比”按上面的堆叠数 N 填入 N、6N、10N、16N，一满格等于原版一格。“填入原版”填 1、6、10、16。

只改玩家自己在交易所卖货这一处（`CTrade::CommitDeal`），舰队自动交易不受影响。四个都是原版值时不写任何东西。补丁代码放在跳板表后 int3 空位的末尾（堆叠代码在开头），开头写着 `DK4FSH1`，末尾存原版字节，改回原版值时原样放回；和堆叠互不依赖，堆叠填 1 也能单独用。

## 地方舰队亏损修正

地方舰队和下属 NPC 舰队自动买货时，成本按 `货价 × (1000 − 船长交易能力 + 随机 0~99) ÷ 1000` 计算。原版能力最高 500，所以最多打五折。属性结算上限放开后能力会超过 1000，括号里变成负数，游戏再按无符号数相除，一次买货就记几百万支出，月报显示亏损上亿。

“写入主程序”每次都会顺带修正：这一处的能力先按 500 封顶再算，等于原版满能力。别处的能力值不受影响。四个语言版都用字节模式定位，补丁代码放在该函数结尾后的空位里。

已经亏出的欠账还在存档里：付不起的亏损会转到下个月支出，修正只能阻止新的亏损。最好读修正前、出问题之前的存档；或者解散该舰队，代价是身上的钱可能被扣光。

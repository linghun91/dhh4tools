# World0 与 World1 内容包差异

配置落点：`packs/vanilla-world0/`、`packs/vanilla-world1/`。剧本选哪一份由 `config/narrative/scenarios.yaml` 的 `world_pack` 决定，见 [01-scenarios.md](01-scenarios.md)。港口 / 人物 / 势力 / 舰队 / 道具的**字段语义**仍归各系统文档；本篇只登记两包之间每一个不同的字段。

## 1. 职责边界

本篇管：

- 原版两份世界 DLL 是同一套 schema、两份实例
- 剧本 0–3 加载 World0、剧本 4–6 加载 World1（原版硬编码；重构后写成显式 `world_pack`）
- 人物六维、港口特产品、势力、舰队模板、道具定义在两包里哪些字节不同

不管：

- EV0–EV6 事件脚本（`02-event-system.md`）
- 公式、上限、UI 文案
- 把 `if scenario_id >= 4` 留在经济 / 战斗 / 航海代码里

原则：World0 / World1 是内容包，不是两套逻辑。缺字段禁止回退到另一包。

## 2. 原版事实

### 2.1 同一套导出，两份表

[确认] `Game/SC/World0.dll` 与 `World1.dll` 导出相同：`GetFixTownProc` / `GetFixPersonProc` / `GetFixItemProc` / `GetFixForceProc` / `GetFixFleetProc`。`CDllManager` 按 `SC/World%d.DLL` 加载。来源：`srcdata/source/world/DllMain.cpp`、`srcdata/source/WorldData.h`、`srcdata/docs/formats.md`。

[确认] 五张表的条数、步长两包完全相同：

| --- | --- | ---: | --- | --- | --- |

### 2.2 剧本怎么选包

[确认] exe `fn_14000ff60`（body `0x1402a89a0`）：

```
if (scenario_id >= 4) return 1;  /* World1.dll */
else                  return 0;  /* World0.dll */
```

因此原版绑定是：

| scenario_id | 主角 | 世界包 | 事件包 |
| ---: | --- | --- | --- |
| 0–3 | 拉斐尔 / 赫德拉姆 / 丽璐 / 华梅 | `vanilla-world0` | EV0–EV3 |
| 4–6 | 杏太郎 / 伍丁 / 蒂雅 | `vanilla-world1` | EV4–EV6 |

重构**不要**把 `>= 4` 写成引擎语义。每条剧本显式写 `world_pack:`。`world_pack_split: 4` 只作为从原版 exe 抽 YAML 的提取规则。来源：[01-scenarios.md](01-scenarios.md)。

### 2.3 对比方法

[确认] 用 Python 对下列三份数据做字段级比对，五张表 hex **零失配**：

1. `srcdata/source/world/World0_{town,person,force,fleet,item}.c` 与 `World1_*.c`
2. `srcdata/catalog/world_tables.json` 的 `World0.dll` / `World1.dll`
3. 交叉：`Docs/_data/*_world0.json` 对 World0 C；`Docs/_data/world1_names.json` 对 World1 C（港名、人名、六维、势力名零失配）

对比时**丢掉 DLL 内指针**（人物 `+0x00..+0x17` 三根姓名指针、道具 / 势力 `+0x00..+0x07` 名指针）。这些字节随 VA 变，不是玩法字段。

## 3. 实体与 ID

两包共用同一套 ID。`NUM_*` 只是原版实例计数，引擎按表长循环。

| 实体 | 原版计数 | 空 / 非法 | 包内是否换 ID |
| --- | ---: | --- | --- |
| `town_id` | 97 | −1；特产品空 106；若干 UI 98 | 否，同名同坐标 |
| `person_id` | 235 | −1；舰队空人物 `0xEC` | 否（202 只改姓名切分） |
| `force_id` | 25 | 头文件 −1；运行时 26 | 否 |
| `fleet_id` | 69 | −1 | 否 |
| `item_id` | 231 | −1；装备空槽 232 | 否 |
| `world_pack` | 2 | 无 | 本篇的主键 |

稳定 key 仍按整数 ID 生成（`london`、`raphael_castro`）。禁止为 World1 另编一套 id。

## 4. 算法 / 公式

本篇没有伤害 / 价格公式。原版唯一硬编码：

```
world_pack_index = 0
if scenario_id >= world_pack_split:
    world_pack_index = 1
```

| 参数 | 原版默认 | 落点 |
| --- | --- | --- |
| `world_pack_split` | 4 | 只作提取规则；运行时读 `scenarios.yaml` 的 `world_pack` |

人物经验、六维、势力影响力的**用法**在各自系统；本包只提供初值。

## 5. 耦合分析

原版焊点：

1. `CWorldData` / `CPerson` / `CTown` / `CFleet` / `CForce` / `CItem` 初始化都 `fn_14000ff60(scenario)` 再 `LoadLibrary("SC/World%d.DLL")` —— 内容选择混进每个系统
2. 其它系统若写 `if scenario_id >= 4` 即违规。World1 的数值差必须已经在内容包里
3. 特产品 6 字节里混了 `trading_item_id`（world 外键）和价量（economy）。两包价量碰巧相同，仍按包各存一份
4. 势力母港 98 与人物 `+0x2A==26`、港口 `+0x4C==26` 是三条平行的「未出场」编码，重构后统一成 `force.active` / `town.occupying_force_id`，不要让三个系统各猜一个 26

允许的方向：叙事选包 → 世界 / 人物 / 势力 / 舰队 / 道具加载该包。禁止经济按剧本号改市价。

## 7. 独立旋钮

改这些不应迫使贸易 / 战斗改代码：

- 某剧本换 `world_pack`（World0 ↔ World1，或模组包）
- 只改 World1 里赫德拉姆六维 / 李家母港 / 某港 `+0x4C`
- 增加第三份世界包（新目录、同 schema、`scenarios.yaml` 引用）
- 把特产品从「两包相同」改成「World1 某港换货」（只动该包 `special_products.yaml`）

需要其它系统配合的只有：新包里出现的 `town_id` / `person_id` / `force_id` / `item_id` / `trading_item_id` 必须在对应表里存在。

## 8. 对外接口

事件：

| 事件 | 载荷 | 谁听 |
| --- | --- | --- |
| `ScenarioSelected` | `scenario_id`, `world_pack`, `event_pack`, `person_id` | 世界加载、人物、势力、舰队、道具、事件解释器 |
| `WorldPackLoaded` | `world_pack`, `schema_version` | 存档会话（记下包 id，不存表原文） |

查询（LIVE，取当前包；取不到则 no-op）：

```
World.pack_id() -> world_pack
World.town(town_id) -> TownDef
Characters.get(person_id) -> PersonDef          # 含该包六维初值
Factions.force(force_id) -> ForceDef
Fleets.template(fleet_id) -> FleetTemplate
Items.get(item_id) -> ItemDef
Economy.special_slot(town_id, slot) -> SpecialProductDef
```

命令：

```
Narrative.select_scenario(scenario_id, seed)  # 内部选包，不把 scenario_id 传给经济
World.load_pack(world_pack)                   # 启动 / 读档
```

只传 ID 与纯值。禁止传 `World*`、DLL 句柄。存档存 `world_pack` id + schema version，不存 97 港原文。

## 9. 未核实字段

| 位置 | 现状 | 禁止 |
| --- | --- | --- |
| 人物 `+0x18/+0x1C` | 81 条有差；宽度像经验 | 不要写成确认的金币 / 名声 |
| 人物 `+0x27/+0x28/+0x2B/+0x2C` | 有差；伍丁 `+0x2B/+0x2C` 像 u16 | 不要当 job / 立绘 id |
| 人物 `+0x2A` | 4 条与势力出场对齐 | 可配 `force_id`，默认值标 [推断] |
| 人物 `+0x30` | 21 条 0/1，与舰队 `+0x16` 同形 | 不要当世界包标记 |
| 港口 `+0x49/+0x4D/+0x4E/+0x52/+0x54` | 78 港窗口内的差 | 不要当发展度 / 份额 |
| 港口 `+0x4C` | 18 条像占领势力 | 可配 `occupying_force_id`，标 [推断] |
| 港口 `+0x46..+0x55` 以外 | 两包全同 | 不要为「找差异」去改这段 |
| 舰队船槽 5 字节 | 45 条有差，值常 > `NUM_SHIP` | 整段 `unknown_bytes` |
| 舰队 `+0x12/+0x14/+0x16` | 见第 2.8 节 | `+0x14` 的 57→99 不要当汉城 |
| 道具 `+0x0C/+0x10/+0x15/+0x18/+0x19` | 126 条 | 坐标 / 发现港只标 [推断] |
| id 203+ 姓名乱码 | 抽出 GBK 失败，两包相同 | 不要为 World1 另造译名 |

提取器：确认字段进 YAML；本篇列出的残余进 `unknown_bytes`；指针丢弃。

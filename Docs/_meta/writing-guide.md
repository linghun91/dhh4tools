# 文档写作规范

本目录是《大航海时代4 パワーアップキット HD》（DK4HD）的**重构设计文档**。目标不是复述反汇编，而是把原版玩法、算法、数值拆成**可独立配置、可替换、可扩展**的设计模块。

## 读者

- 玩法策划：改表、改公式、加港口/人物/商品
- 程序：按接口实现系统，不把数值写进代码
- 工具链：从 `config/` 生成运行时数据

## 每篇系统文档必须包含的章节

1. **职责边界** — 本系统管什么、不管什么
2. **原版事实** — 只写能在仓库里指到的事实。每条事实给来源：
   - 头文件 / 世界表 / 存档 / 反编译 cpp / mesfile / 已有 `srcdata/docs`
3. **实体与 ID** — 命名空间 key、计数（注明证据类型：判界 / 循环上界 / RTC 投票）、运行时空值（`null`）；原版哨兵只写在本节对照并指向 `config/ids/legacy_codec.yaml`
4. **算法 / 公式** — 用**命名参数**写，禁止把 `30`、`100`、`150` 这种魔数只写在公式里不入库
5. **耦合分析** — 原版硬编码依赖了哪些别的系统
6. **解耦后的配置** — YAML 示例，文件落在本系统自己的 `config/<domain>/`
7. **独立旋钮** — 改这些值不应迫使其他系统改代码
8. **对外接口** — 事件、查询、命令。只暴露 ID 与值，不暴露内部表结构
9. **未核实字段** — 世界表 hex 里尚未命名的字节必须单列，禁止猜成确定语义

## 事实等级

| 标记 | 含义 |
| --- | --- |
| `[确认]` | 有表、有公式、有断言或有手写还原 |
| `[推断]` | 从布局/循环/文案合理推出，但字段名原版未恢复 |
| `[未知]` | 有字节或有符号，语义未还原 |

推断必须写清依据。禁止把推断写成确认。

额外规则：

- `NUM_*` 来自 RTC 立即数投票（`srcdata/tools/fill_gaps.py`）的，只能 `[推断]`；`[确认]` 要有判界或循环上界。
- 反编译里的常数、除数、参数要回原始指令核对：`cdq; sub; sar` 前的寄存器残留、上一调用留下的参数寄存器常被当成公式常数，`imul` 立即数与 `idiv` 除数常丢。
- 地址换文件偏移按 PE 段：`.text` −`0x140000A00`、`.rdata` −`0x140001200`、`.data` −`0x140001600`。
- 函数名写 thunk 时同时给 body 地址。

## 解耦铁律

- **ID 是唯一共享词汇。** 系统之间只传 `town_id`、`person_id`、`trading_item_id` 等，不传结构体指针，不传 `World*`。主键是命名空间 key；运行时空值是 `null`，不用原版哨兵整数（D1）。
- **一张表只属于一个系统。** 港口坐标属于 world，港口市价属于 economy，港口驻军属于 factions。同一港口用同一个 `town_id` 关联。
- **公式与内容分离。** `formulas/*.yaml` 只放算法参数；内容表只放实例。
- **World0 / World1 是内容包，不是两套逻辑。** 同一 schema，两份数据。
- **上限全部进 caps.yaml。** 等级、技能、港口发展度、堆叠、金币、友好度，一律可配。
- **硬编码循环上界视为 bug。** `NUM_TOWN=97` 只作为原版数据包的实例计数，运行时读表长。
- **时间与随机数是引擎服务。** 系统订阅日历事件（`DayStarted` / `MonthStarted` …），从自己的 RNG 流取随机；不自建计时器，不调全局 `rand`。见 `00-overview/05-config-architecture.md`。
- **事件 / 查询名先查 `00-overview/06-system-interfaces.md`，YAML key / 修正器 key / caps 键 / tick 阶段名先查 `00-overview/10-key-glossary.md`。** 新名字登记在那里；已有别名的不再新造。
- **修正器统一出口。** 跨系统数值走 `Modifiers.eval(key, ctx)`（按 key 的注册表，不是写死字段的结构体），提供方注册带来源的贡献；不读六维原值（D2）。
- **代码与公式里不比较字面量 id、不比较剧本号。** 船首像、岗位、技能、舱室种类改成内容表 `effects` / `role` / `refs`；剧本差异走 `scenario_flag` / 剧本修正器（D3、D5）。
- **派生量只有一个计算方。** 消费方读快照，不自己重算、不存档（D6）。
- **跨系统决策以 `00-overview/09-architecture-decisions.md` 为准。**

## 配置文件约定

```
config/
  caps.yaml                 # 全局上限
  modifiers.yaml            # 修正器 key 注册与阶段序
  engine/                   # tick 顺序、RNG 流
  formulas/                 # 命名公式
  ids/                      # key ↔ vanilla_index（生成）；legacy_codec.yaml 原版哨兵（仅导入导出）
  world/                    # 地图、海域、港口、村落、遗迹、航线
  factions/                 # 势力、国家、文化、流行、关系
  characters/               # 人物、职业、技能定义、岗位
  economy/                  # 交易品、文化圈卖价、景气价格规则、特产品、投资
  ships/                    # 船型、舱室、火炮、补给、船首像
  fleets/                   # 舰队模板、委任、阵型
  combat/                   # 海战、接舷、AI
  ocean/                    # 航行、风向、探索、黄金航路
  town/                     # 设施、委托、计略、小游戏
  items/                    # 装备/发现物效果
  discovery/                # 古地图、解谜、霸者之证
  narrative/                # 剧本、事件触发
  progression/              # 等级、经验、Game Over（原版无名声）
  ui/                       # 场景流、文案 key、存档旋钮 save.yaml
  localization/             # 语言表
```

YAML 里用蛇形英文 key，运行时显示只走 `name_key` / `desc_key`（文本进语言包）；`name` 里的中文只作导入对照与注释。跨包引用用命名空间字符串 key（`vanilla:london`）；整数只是原版下标与运行时紧凑下标，模组不手写整数 ID。规则见 `00-overview/05-config-architecture.md`「ID 与命名空间」「覆盖与合并」；完整目录树也在该篇。

## 禁止

- 把 UI 字符串写进逻辑配置
- 一个 YAML 同时描述战斗伤害和市价
- 用「参考大航海4」代替具体公式
- 编造未在源数据出现的港口、人物、商品
- 修改 `srcdata/` 或 `Game/` 下的任何文件

## 语言

正文中文。标识符、文件名、YAML key 英文。引用原版类名保持 `CTrade`、`eTown` 这种形式。
